# Xray через Marzban на Ubuntu

Разворачивай Marzban с VLESS TCP REALITY и проверяй результат реальными подключениями. Пользователь может попросить только аудит, подготовку установщика, установку нового VPS или исправление существующей панели — соблюдай выбранный объём работы. Само применение навыка не разрешает подключение к чужому серверу или изменение рабочего VPN.

## Выбор режима

- **Новый VPS:** прочитай [процедуру развёртывания](references/deployment.md); используй `scripts/deploy.py` с отдельным JSON по образцу `assets/deploy.json.example`.
- **Существующий сервер / ошибка запуска:** сначала прочитай [диагностику](references/troubleshooting.md). Не запускай fresh-install поверх существующей БД, ключей или firewall.
- **Только инструкция/автоматизация:** создавай локальные файлы; не подключайся к VPS без соответствующего запроса.

## Контекст и параметры

Получай адрес VPS, SSH-порт, пользователя и способ аутентификации из текущего запроса. Перед изменениями проверь ОС, слушающие порты, службы, Docker, каталоги панели, ACME-клиенты, UFW и DNS. Не удаляй компоненты образа провайдера только потому, что они не нужны Marzban.

Установщик поддерживает чистые Ubuntu 24.04/26.04 LTS. Базовый сценарий реально проверен на Ubuntu 26.04.1; это не гарантия совместимости всех будущих образов. Для другой ОС адаптируй и проверь зависимости, не обходи проверку версии вслепую.

Домен панели, email, имя администратора, порты SSH/панели и цель REALITY задаются явно для текущей установки. В шаблоне они пустые; не наследуй их от предыдущих серверов. Зарезервированные example.org/example.net и вымышленные значения в тестах не являются рабочими настройками. Базовый профиль использует VLESS на TCP 443 и HTTP-01 на TCP 80. Wildcard в описании имён не означает запрос общего wildcard-сертификата: конкретный поддомен получает отдельный SSL через HTTP-01. Настоящий wildcard требует DNS-01.

## Инварианты установки

1. Используй предоставленный SSH-ключ. Если нужен новый, храни приватную часть только в защищённом локальном файле и передай пользователю путь; на VPS отправляй `.pub`. Пароли читай из предназначенного пользователем файла/секретного ввода без вывода в журнал. Ошибка интерактивного SSH-клиента не доказывает, что пароль неверен: прямое чтение файла через SSH-библиотеку помогло в проверенном сценарии. Проверяй host key; несовпадение не обходи автоматическим принятием.
2. Сначала сертификат и его файлы, затем HTTPS-панель. Для новых VPS скрипт использует Certbot, deploy-hook и timer. Сохраняй работающий acme.sh на существующем сервере; не устанавливай второй ACME-клиент без необходимости.
3. `XRAY_SUBSCRIPTION_URL_PREFIX` включает нестандартный HTTPS-порт. SQLite и Xray-конфиг лежат в постоянном `/var/lib/marzban`; env/Compose — в `/opt/marzban`.
4. Выбирай стабильный релиз и фиксируй digest образа после загрузки. Пример `v0.8.4` — проверенная исходная версия, не обещание актуальности. Перед новой установкой проверь релизы/совместимость. Не включай dev, автообновления образа, ежедневные reboot или перегенерацию REALITY-ключей по умолчанию.
5. Для REALITY нужны hostname цели, SNI, уникальные privateKey/shortId и flow `xtls-rprx-vision` у пользователя. Адрес VPN-клиента — VPS, не сайт маскировки. Проверяй TLS 1.3/h2 цели с VPS; это не заменяет тест VLESS.
6. При смене SSH сохраняй исходный доступ до нового входа по ключу и проверки sudo. Связку `prepare → finalize → confirm` выполняй именно с новыми SSH-сессиями; таймер отката ставится до изменения основного sshd. Учитывай `ssh.socket`, Include/Match и конфиги провайдера. Не отменяй откат до успешного входа. Не перезагружай сервер во время перехода.
7. В UFW сначала разреши необходимые порты, затем включай. Для базового TCP REALITY не открывай UDP 443 и Shadowsocks 1080. Если нужны дополнительные inbound, определяй протокол по конфигу. `network_mode: host` и Docker bridge с published ports требуют разного анализа firewall.

## Завершение и проверки

Создай администратора панели без пароля в argv или `.env`, проверь внешний HTTPS и API-вход, новый SSH штатным клиентом, UFW, Xray, Fail2ban, Certbot timer и dry-run продления. При уместном тесте VPN используй временного пользователя/клиент и удаляй их в `finally`; не оставляй тестовый HTTP/SOCKS-proxy доступным извне.

`scripts/backup.py` делает согласованную копию с короткой остановкой панели и попыткой запуска в `finally`. Это локальная копия, не автоматический внешний backup. Перезапуск прерывает активные VPN-соединения; учитывай контекст рабочего сервера.

Проверка скриптов: `python3 -m unittest discover -s scripts -v`. Не выдавай unit-тесты за установку на реальном VPS. При частичном сбое prepare не удаляй state ради повторного запуска: установщик не поддерживает автоматический resume. Исследуй этап и продолжи точечно либо используй действительно новый VPS.

В результате укажи адрес панели, SSH-пользователя/порт, защищённые пути к данным входа, проведённые проверки и оставшиеся ограничения. Не печатай пароли/ключи в общий отчёт, не включай их в skill или архив установщика. Не утверждай проверку из сети пользователя или после reboot, если её не выполнял.
