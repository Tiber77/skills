# Диагностика существующего VPS

## SSH

Таймаут до запроса пароля означает проблему доступности/порта/firewall, а не неверный пароль. Permission denied проверяется отдельно. Не перебирай варианты пароля. Если пользователь подтверждает рабочий пароль и даёт файл, прочитай его напрямую (убери только BOM и завершающий CR/LF, не внутренние символы/пробелы), передай библиотеке SSH без логирования. Это обходит ошибки передачи ввода Windows PTY. Сохраняй проверку host key и сетевые разрешения инструмента.

При смене порта сравни `sshd -T` и `ss -lntp`, затем состояние `ssh.socket` и `systemctl cat ssh.socket ssh.service`. В Ubuntu socket может продолжать слушать 22 при новом Port в sshd_config. Учитывай как генератор systemd после daemon-reload, так и явные drop-in ListenStream. Несколько Port могут включать несколько портов. Старое установленное SSH-соединение может жить после изменения listener — нужна новая сессия.

Проверяй Include/Match, cloud-init и настройки нового администратора до запрета root/password. На рабочем сервере не подменяй основной конфиг fresh-install шаблоном без анализа остальных правил и пользователей.

## Marzban не запускается

Из traceback выдели первую фатальную ошибку. Предупреждение pkg_resources deprecated само по себе не объясняет падение.

При `SSL certificate file ... does not exist` сопоставь `.env`, реальные файлы хоста и volume контейнера. Не печатай приватный ключ. `/var/lib/marzban:/var/lib/marzban` делает пути одинаковыми, но каталог должен существовать. Симлинки из `/etc/letsencrypt/live` требуют доступности archive; копирующий deploy-hook решает это в базовом установщике.

Для существующего acme.sh используй `--install-cert -d DOMAIN --ecc --key-file ... --fullchain-file ... --reloadcmd ...`, а не ручное копирование из его внутренней папки. Проверь cron/timer и метод challenge. Не смешивай acme.sh и Certbot для одного сертификата без необходимости.

Если HTTPS временно выключен в Marzban, доступ может быть ограничен localhost. Для диагностики используй SSH-туннель; внешний HTTP без защиты не является постоянным решением.

## UFW и порты

Сверяй `ss -lntup` с UVICORN_PORT и реальными inbound. Не открывай порт только потому, что его номер похож на стандартный. API Xray на localhost не требует внешнего разрешения. Shadowsocks TCP/UDP открывай только если этот inbound действительно нужен.

При UnicodeDecodeError во время подтверждения ufw проверь сохранённые разрешения SSH и используй `ufw --force enable`. Это обход ошибки интерактивного ввода, а не основание сбрасывать firewall. Всегда проверяй новый SSH-вход после включения.

## REALITY и подписки

Цель должна быть доступна с VPS, поддерживать требуемый TLS и согласованный SNI. Не подменяй выбранную пользователем цель другой без объяснения. При нерабочем клиенте проверь адрес VPS, flow, pbk, shortId, SNI, порт/transport, Host Settings и ссылки, реально возвращённые API. Не перегенерируй ключи действующим пользователям ради диагностики.

После первичного создания пользователя/Host Settings возможно ожидание обновления состояния: запроси пользователя повторно с ограниченным числом попыток. Отсутствующий параметр в ссылке исследуй; не подставляй молча иной ключ/shortId в клиент и не объявляй исходную подписку рабочей.

Ошибки домена панели и REALITY независимы: SSL панели относится к домену VPS, REALITY использует сайт маскировки. XRAY_SUBSCRIPTION_URL_PREFIX должен включать нестандартный HTTPS-порт.
